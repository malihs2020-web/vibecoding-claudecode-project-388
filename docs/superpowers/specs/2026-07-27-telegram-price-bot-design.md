# Дизайн: telegram-price-bot

Дата: 2026-07-27

## Проблема

Сейчас `tracker` (skill) отслеживает цену только одного зашитого товара (корм Premier) по зашитому списку URL, и запускается вручную в чате. Пользователь хочет писать название произвольного товара прямо в свой Telegram-бот и получать обратно топ-5 самых дешёвых точных совпадений со ссылками — без правки кода под каждый новый товар.

## Ограничения, определившие архитектуру

Обсуждали три желаемых свойства — все три одновременно невозможны:

1. Полностью автономная работа 24/7, без открытого чата с Claude.
2. Токен Telegram-бота хранится только на компьютере пользователя (не в облачных настройках расписания).
3. Проверка маркетплейсов (Ozon/Яндекс Маркет/Wildberries) — они требуют браузер (Claude in Chrome), которого нет у облачного расписания.

Требования (2) и (3) вместе означают, что опрос Telegram и поиск должны выполняться на компьютере пользователя, внутри активной сессии Claude Code с подключённым браузером. Пользователь выбрал пожертвовать пунктом (1): «круглосуточно» на практике означает «пока открыт чат Claude Code на компьютере».

## Архитектура

Новый skill `.claude/skills/telegram-price-bot/SKILL.md`, независимый от `tracker` (тот остаётся как есть, для корма Premier — рекуррентное отслеживание с baseline/diff). Новый skill — одноразовый поиск по запросу, без сохранения истории и без сравнения с прошлым.

Два режима, включаются текстовой командой в чате:

- **Старт: «слушай телеграм»**
  1. Напомнить пользователю обе команды (старт и стоп) — на случай, если забыл.
  2. Зафиксировать текущий `last_update_id` из Telegram (см. «Состояние» ниже) — чтобы не реагировать на старую переписку, случившуюся до старта.
  3. Запланировать первую проверку через ~3 минуты (`ScheduleWakeup`, тот же механизм, что у `/loop` в динамическом режиме).

- **Стоп: «хватит слушать»**
  1. Отменить запланированные проверки (`ScheduleWakeup` c `stop: true`).
  2. Подтвердить пользователю, что опрос остановлен.

## Поток данных на каждой проверке (просыпание раз в ~3 минуты)

1. Вызвать новый скрипт `receive.py` (лежит в корне проекта рядом с `send.py`) — он читает `TELEGRAM_BOT_TOKEN`/`TELEGRAM_CHAT_ID` из `.env` (как `send.py`) и делает `getUpdates?offset=<last_update_id+1>`. Возвращает JSON: список новых сообщений (`update_id`, `chat_id`, `text`), отфильтрованных по `TELEGRAM_CHAT_ID` (сообщения из чужих чатов игнорируются).
2. Нет новых сообщений → тихо обновить `last_update_id` (если изменился) и запланировать следующую проверку через `ScheduleWakeup` — без сообщений пользователю (аналогично «молча перепланировать» в примере автономного триггера).
3. Есть новые сообщения → обработать каждое по очереди (по порядку `update_id`), для каждого:
   a. Текст сообщения = название/описание товара.
   b. Найти источники: **не использовать зашитый список URL** — вместо него применить уже описанные в `tracker` шаги «Порядок действий: fallback-поиск сторонних магазинов» (WebSearch, исключая ozon.ru/market.yandex.ru/wildberries.ru) и «Порядок действий: Ozon / Яндекс Маркет / Wildberries» (браузер доступен, т.к. сессия активна) — переиспользовать эти разделы `tracker/SKILL.md` как есть, а не дублировать текст.
   c. Применить «Общее правило точного совпадения» (тоже из `tracker`) для отсева неподходящих по весу/вкусу/размеру вариантов.
   d. Для каждого кандидата вызвать skill `extract-price`.
   e. Из результатов со статусом `ok` и `exact_match: true` отсортировать по цене (`sale_price`, если есть, иначе `regular_price`) по возрастанию, взять топ-5.
   f. Собрать ответ:
      - Есть результаты → `Нашёл по запросу «<текст>»:` + до 5 блоков (источник, цена, ссылка на отдельной строке — тот же формат, что уже используется в сводке `tracker` для Telegram).
      - Нет ни одного точного совпадения → `По запросу «<текст>» ничего подходящего найти не удалось`.
   g. Отправить ответ через `python send.py "<текст>"`.
4. Обновить `last_update_id` (файл состояния) на максимальный обработанный `update_id`.
5. Запланировать следующую проверку через `ScheduleWakeup` (~3 минуты, обоснование в `reason`: «жду новых сообщений в телеграм-боте»).

## Состояние между проверками

Локальный файл `telegram_bot_state.json` в корне проекта — `{ "last_update_id": <число> }`. Не коммитится в git (добавить в `.gitignore`, рядом с `.env`) — это временное рантайм-состояние конкретного запущенного цикла, а не то, что нужно сохранять между сессиями/машинами.

## Обработка ошибок

- `receive.py` не смог достучаться до Telegram (сеть/API) → не считать это сбоем всего цикла: пропустить эту проверку молча, повторить на следующей запланированной проверке. Не оповещать пользователя из-за единичной заминки.
- По конкретному товарному запросу ни одного точного совпадения не нашлось → явно сообщить об этом пользователю в Telegram (см. шаг 3.f), не подставлять цену "на глаз" и не пытаться угадать.
- `send.py` не смог отправить ответ → как и в `tracker`: не считать сбоем всего цикла, не повторять попытку в обход `send.py`; в следующий цикл жизни это не блокирует.
- Несколько сообщений накопилось между проверками → обработать все по порядку, ответить на каждое отдельным сообщением в Telegram — ни один запрос не должен потеряться молча.

## Переиспользование существующих skill'ов

- `extract-price` — без изменений, вызывается как есть.
- `tracker` — секции «Общее правило точного совпадения», «Порядок действий: Ozon/Яндекс Маркет/Wildberries/fallback-поиск» переиспользуются по ссылке (кросс-референс на `tracker/SKILL.md`), не дублируются текстом в новом skill'е. Секции `tracker`, специфичные для корма Premier (зашитый список URL, топ-5-baseline, diff с предыдущим прогоном, сохранение в `tracker-data`) — не используются `telegram-price-bot`, он не пишет и не читает `tracker-data`.

## Тестирование / проверка

Ручная проверка (это не код с юнит-тестами, а поведенческая логика skill'а):

1. Написать в чате «слушай телеграм» — убедиться, что пришло напоминание про обе команды и что цикл проверки запущен (первая проверка запланирована).
2. Написать боту название любого товара — убедиться, что через ~3–5 минут в Telegram пришёл топ-5 (или честное «не нашёл») со ссылками.
3. Написать в чате «хватит слушать» — убедиться, что больше проверок не происходит.
4. Проверить сценарий «ничего не нашлось» на заведомо несуществующем товаре.
5. Проверить, что старая переписка в боте (до команды старта) не вызывает повторной обработки.
